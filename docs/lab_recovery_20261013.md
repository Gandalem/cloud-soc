## AWS 웹 로그와 실제 포털

개발 PC/Ubuntu의 AWS 22 연결 시간 초과 후 사용자가 현재 출발지에 인바운드를 허용했다. 사용자가 AWS 콘솔에서 확인한 ED25519 지문과 연결 지문을 대조한 뒤 지정 개인키로 인증했다. 개인키는 중앙에 복사하지 않았다.

기존 AWS producer의 큐·stream과 DVWA를 유지했다. AWS→VM의 직접 경로가 없어 VM에 새 web-only relay를 설치했다. 중앙에서 생성한 목적 전용 키의 공개 부분만 AWS에 추가했고 출발지 제한·forced command를 적용했다. 공개 키 옮김의 오타는 검증된 공개 파일에서 다시 읽어 보정했으며 다른 authorized_keys를 보존했다. 기존 큐/접근 기록을 보호 백업했다.

기존 AWS producer의 spool/metadata/entry 공개 코드 3개는 최신 main의 Git 바이트 해시와 일치했다. 실행 중인 producer나 DVWA를 재시작하지 않고 최신 코드 유지와 새 전달 경로를 각각 확인했다.

새 전용 raw 인덱스·strict mapping·web-only 수신 pipeline·정확한 index의 create_doc만 있는 30일 게시 키를 준비했다. 기존 글로벌 수신 pipeline·역할·OS 수집 endpoint는 변경하지 않았다. 기존 큐 5건과 정상 GET/리다이렉트 2건을 VM으로 전달해 **raw 7건 → web 정규화 7건 → 관리자 포털 목록 7행**을 대조했다. 불변 정규화 ID 직접 조회로 각 원본 참조·어댑터·정규화 해시를 확인했다.
