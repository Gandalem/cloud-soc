## 운영 복원 시 수행할 순서 — 아직 미실행

1. 현재 VM 스냅샷과 원본 디스크 보존본을 유지하고, 운영 인덱스/호스트 상태 변경 전 보호 사본을 확보한다.
2. 원본 수집·정규화·탐지·Slack 작업자의 실행/재시작 정책을 확인하고 복원 중 쓰기와 과거 경보 발송을 막는다. `enrollment-cleanup`은 계속 비활성/정지한다.
3. 기존 인덱스와 충돌하는 항목을 범위별로 명시한 뒤 위 10개 인덱스의 운영 이름 복원을 수행한다. 글로벌 cluster/security state와 alias를 무심코 덮어쓰지 않는다. 시험 복원 인덱스를 운영 전환 완료로 간주하지 않는다.
4. 10월 21일 원본과 스냅샷에 없는 인덱스는 별도 보존한다. 전 범위 wildcard 삭제, 빈 primary 강제 할당, 파일 단위 Lucene 수정은 사용하지 않는다.
5. 10월 21일 호스트 체크포인트를 10월 16일 복원 데이터에 그대로 연결하지 않는다. 기존 상태를 보관하고 복원 기준선/향후 신규 수집 시작 경계를 별도 계획으로 고정한다. 이후 정상 원본을 재분석해 부분 복구 경로로 되돌아가지 않는다.
6. Kibana는 스냅샷에 없으므로 별도 보존/재구성 계획이 필요하다. 기존 저장 객체 손실 가능성을 스냅샷 복원 성공으로 감추지 않는다.
7. primary 활성화뿐 아니라 문서 조회, 운영 데이터 범위, 정규화/탐지 진행, 새 로그와 Slack 발송을 확인하고 재시작 정책을 복원한다. 과거 경보 일괄 재발송은 하지 않는다.

이 문서는 복원 선택과 남은 실행 범위를 기록한다. 무인 운영 전환 스크립트가 아니며,
현재 Git 요청에서 VM 인덱스 교체·체크포인트 초기화·Kibana 삭제를 수행하지 않았다.
