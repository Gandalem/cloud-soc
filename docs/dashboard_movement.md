# 내 대시보드 위치 이동

DASHBOARD-MOVE-01, 2026-10-20. codex/operational-readiness의 기존 개인 대시보드 편집을 보완한다.
최신 사용자 지시로 테스트·브라우저 조작·린트·구문 검사·실제 저장 확인을 수행하지 않는다.
아래는 작성한 동작의 설계이며 실제 검증 결과가 아니다. 제품 화면에는 개발 진행 문구를 넣지 않는다.

## 조작

- 편집 중 위젯 제목 영역이 이동 핸들이다. 제목 클릭 또는 이동 버튼으로 클릭 배치를 시작한다.
- 제목을 일정 거리 끌면 위치 미리보기를 보여 준다. 다른 위젯의 위/아래 절반에서는 앞/뒤 삽입을 제안하고 빈 공간에서는 격자 위치를 제안한다.
- 끄는 동안 기존 위젯 위치는 바꾸지 않는다. 화면 위/아래 가장자리에서는 페이지를 스크롤한다.
- 클릭 배치에서는 다른 위젯의 앞에 놓기/뒤에 놓기 버튼을 선택한다. 넓은 화면에서는 빈 격자 공간도 선택할 수 있다.
- 이동 취소 버튼과 Esc는 배치를 바꾸지 않고 종료한다. 포인터 취소/캡처 유실/창 전환/화면 크기 변경도 드래그를 취소한다.
- 작은 화면에서는 세로 스크롤과 충돌하는 드래그 대신 제목/이동 버튼과 앞/뒤 배치 버튼을 사용한다.
- 제목 핸들은 키보드 버튼이고 대체 위치 버튼도 키보드로 선택할 수 있다. Alt+위/아래도 인접 위젯을 기준으로 이동한다.
- 크기 조절은 별도 핸들/설정으로 유지하며 이동 제목과 섞지 않는다.

## 배치와 상태

기존 layout schema, 위젯 ID/type/config, x/y/w/h, revision 기반 저장 API를 유지한다.
기존 저장 배치는 페이지 진입이나 이동 시작/미리보기만으로 재정렬하지 않는다.
선택한 위젯을 목적지에 고정하고 실제로 겹치는 위젯만 아래로 밀며, 전체 화면을 일괄 압축하지 않는다.
그 결과의 겹침 연쇄도 아래로 이동시키며 y 상한을 넘는 목적지는 거부한다. 관계없는 위젯의 크기/가로 위치/빈 공간을 보존한다.
다른 목적지에서 같은 위젯 ID를 새로 만들지 않는다. 조회 데이터·경보·원본·조직 범위는 변경하지 않는다.
취소나 실패는 undo 기록을 만들지 않는다. 실제 배치 변경은 한 번의 undo 단위다.
놓기는 메모리 내 편집만 갱신하며 구성 저장 버튼을 눌러야 서버에 저장한다.
다른 편집/저장/렌더링 전 활성 미리보기를 해제하고 포인터/스크롤 작업을 정리한다.
기존 저장 실패/충돌·취소 복원·AJAX 편집 중 갱신 억제 흐름을 사용한다.

## 범위와 기록

변경 파일은 prototype/dashboard-{builder.js,builder.css,widgets.js}와 dashboard.html이다.
새 라이브러리, 자동 정렬 모드, 그룹/탭, 다중 선택, 레이아웃 이관은 추가하지 않는다.
현재 실습 Portal이 읽는 release에 네 개 정적 파일만 백업 후 교체하며 서비스 재시작/재부팅은 하지 않는다.
배포 수행 여부와 검증 미실시는 docs/work_tracker.md에 구분해 기록한다.
실제 브라우저 이동/자동 스크롤/모바일/취소/되돌리기/저장 후 복원 인수는 사용자 지시로 실행하지 않은 후속 항목이다.

정적 파일 교체는 기존 파일 백업 후 수행했다. 실제 화면·API 요청·저장 확인 및 서비스 상태/재부팅 검사는 수행하지 않았다. 작업 목록에 배포 위치와 백업을 기록했다.
