## 공통 계약

`detection/authoring.py`의 schema_version=1 정의를 폼·CSV·JSON·서버 검사·엔진 변환이 공유한다.
새 외부 의존성은 추가하지 않았다. 기존 표준 라이브러리 SQLite/CSV/JSON과 엔진을 재사용한다.
기존 YAML·프로필·배포 규칙 hash·엔진 revision·기존 점수 계산은 그대로 유지한다.

폼은 단일/횟수/실패 후 성공/ModSecurity SQLi 및 기존 Mall Edge SQLi를 제공한다.
지원 출처별 필드/자료형/연산자를 제한하고 서버에서 조직 조건을 강제한다.
웹은 조직/호스트/사이트/IP를 강제로 분리한다. 순서 규칙은 계정도 분리한다.
로그의 없는 필드나 시각·공격 성공을 추측하지 않는다. 조건은 AND이며 임의 코드·정규식·쿼리는 받지 않는다.
신규 형식/알고리즘은 코드 소유 확장이 필요하다. 모든 기존 19종을 폼으로 완전히 표현한다고 선언하지 않는다.
기본 제공 규칙은 읽기 카탈로그로 보이고 표현 가능한 5종은 복제용 정의를 제공한다.
기본 제공 CLI 워커의 선택을 이 화면이 임의 변경하거나 중단하지 않는다.

## 상태·버전·삭제

기존 Portal `cases.sqlite`에 이름이 분리된 managed_* 테이블만 추가한다.
기존 rule_drafts/rule_history·사건·세션은 이관/삭제하지 않는다. 이전 YAML 초안 API도 유지한다.
초안은 편집 가능하고 승인본은 managed_versions에 불변 기록한다.
수정은 새 workflow version이고, 이미 실행 중인 승인 버전은 새 적용 요청 전까지 그대로 둔다.
키는 조직 내 유일하며 삭제 후 재사용하지 않는다. 정수 버전+내용 hash로 동시 변경을 거부한다.

`managed_releases`는 생성 세대/승인 버전/명시 UTC 적용 시작/요청자/시각을 보존한다.
적용 요청은 성공적인 실행이 아니다. requested_version/observed_version과 세대/60초 heartbeat를 구분한다.
생성만 한 초안은 즉시 목록에서 삭제할 수 있다. 한번 적용 요청한 규칙은 삭제 대기로 두고 워커 중단 ack 후 삭제한다.
워커 미실행/장애/미관측을 삭제 완료로 위장하지 않는다. 감사·과거 승인본·경보·증거는 남는다.
권한은 기존 관리자/조직 LogPrincipal·CSRF·Origin/Host 검사를 재사용한다.

## 일괄 등록

CSV 양식 다운로드 또는 JSON `{schema_version:1,rules:[...]}` 입력.
UTF-8 파일 256KiB/배치 100개, 전체 저장 규칙(삭제 이력 포함) 2000개,
규칙별 workflow version 10000 미만. 한 조건의 CSV는 단순 편집용이고 복합 조건은 JSON 왕복 보존용이다.
CSV group_by는 세미콜론 목록, in 값은 JSON 배열, exists는 JSON boolean이다.
파일 미리보기는 행별 오류/요약을 제공하고 선택한 행만 등록 가능하다.
선택 행 전체가 유효해야 하나의 로컬 트랜잭션으로 초안을 생성한다.
request_id+actor+전체 내용/선택 hash의 재전송은 같은 결과, 다른 내용은 충돌이다.
전역 HTTP 8KiB 제한은 유지하고 관리 가져오기 요청만 JSON escape 포함 2MiB까지 허용한다.
파싱 후 원래 content UTF-8 256KiB를 별도로 검사한다.
기존 승인본/실행 규칙은 파일 업로드로 교체·삭제하지 않는다.

## 명시 실행 경계

새 관리 작업자는 기존 incremental.py/early.py의 SQLite/체크포인트를 열지 않는다.
운영 서비스·기존 키·런타임 release policy를 자동 변경하지 않는다.
실행하려면 운영자가 정확한 범위를 승인한 별도 프로세스로 구성해야 한다.
예시의 인덱스 이름은 자리표시자이며 실제 환경에 맞는 concrete 인덱스로 바꿔야 한다.
입력 raw/normalized와 출력 alert/revision 인덱스는 서로 겹칠 수 없다.
aliases/data streams/wildcards를 거부하고 모든 인덱스는 사전 준비되어야 한다.
출력 두 인덱스에는 기존 cloud_soc.provenance enabled:false 매핑이 필요하다. 워커는 매핑을 변경하지 않는다.

```text
python -m cloud_soc.detection.managed_cli
  --config /private/managed-rules.json
  --library /private/portal-state/cases.sqlite
  --es-url https://soc.example.invalid:9200
  --ca-file /private/ca.crt
  --api-key-file /private/managed-worker.key
  --interval 5
```

위는 여러 줄 인자 설명이며 그대로 실행할 셸 명령은 아니다.
설정/키는 소유자 전용 파일로 읽고 TLS CA·호스트 검증, timeout15초, 자동 재시도0, 연결 종료를 적용한다.
키 파일은 JSON이 아니라 기존 protected_key 계약의 encoded API key 한 줄이다. Windows의 실제 비공개 ACL은 배포자가 설정해야 한다.
최소 권한은 정확한 입력 인덱스 read/view_index_metadata와 출력 두 인덱스 read/create_doc/view_index_metadata다.
키 발급·권한 확대·인덱스 생성·서비스 설치는 이번 코드에서 자동 실행하지 않는다.
구성된 endpoint identity도 상태에 고정하며 변경하면 기존 상태를 자동 재사용하지 않는다.
경보 인덱스는 Portal이 읽는 인덱스와 일치해야 한다. Mall 인덱스는 기존 MALL_LAB_SCOPE를 명시해야 한다.

## 경보 시간·재처리·불변성

5분은 이동 집계 범위이지 표시 전 대기가 아니다. 수신 완료한 입력에 조건이 성립하면 같은 cycle에서 경보를 만든다.
초기 문맥을 포함해 현재 시각까지 완전한 PIT를 읽으며 최대 문서 수로 작업량을 제한한다. 집계창 단위로 읽기를 지연하지 않는다.
기본 poll5초이며 실제 지연에는 수집/정규화·검색 refresh·부하·화면 갱신도 포함된다. UI 새로고침은10초다.
기존 900초 frontier를0으로 바꾸지 않고 관리 규칙용 독립 경로를 제공한다.

규칙/실행 세대별 checkpoint와 이벤트 버퍼를 같은 로컬 트랜잭션으로 저장한다.
스냅샷 PIT를 끝까지 읽기 전에 판단하지 않으며 부분 조회/용량 초과/저장 실패면 checkpoint를 보존한다.
원본 바이트는 새로 수집하지 않고 기존 normalized→raw 정확한 참조/event_hash를 유지한다.
버퍼는 이동창+성공창+cooldown+명시 late allowance만큼의 문맥을 재현한다.
배치/순서 변경에 영향을 받는 cooldown은 영속 경보 기록으로 억제하고 기존 경보를 철회하지 않는다.

논리 경보 ID는 관리 규칙 identity+engine rule revision+원본 observation identity로 고정한다.
원격 create 성공 후 응답 유실/로컬 실패는 정확한 ID get으로 원본 경보를 회복하고, 같은 키의 다른 내용은 충돌 처리한다.
추가 지연 증거는 별도 revision 인덱스에 원본 index/id 링크를 붙여 create-only 저장한다.
기존 원본/정규화/경보는 덮어쓰지 않는다. 추가 증거가 기존 증거를 대체/제거하는 경우는 분석 문맥 변경으로 기록한다.
기존 통지기는 원래 경보 인덱스를 대상으로 하며 revision을 새 경보로 발송하지 않는다.
다만 실제 Slack 채널 수신과 새 index로의 전달은 이번 로컬 시험으로 확인하지 않는다.

현재 허용 범위를 넘는 늦은 입력·미래 시각·필수 필드 누락은 참조+고정 사유로 남긴다.
근미래 입력은 허용한 clock skew 범위 안에서 대기 버퍼에 보존한다.
미관측/문제 입력을 안전 판정이나 정상적인 탐지0건으로 해석하면 안 된다.
오래된 입력의 명시 재분석 UI, 기존 경보 철회·사건 자동 조정은 후속 범위다.
max_events와 max_alerts 한도에 도달하면 상태를 보존하고 실패하며 조용한 자동 삭제/오래된 키 재사용은 없다.
