# 참고 도구: Stratus Red Team

검토일: 2026-09-21. 상태: 공식 문서 검토 및 Cloud SOC 검증 계획 참고. 도구 설치/실행, 클라우드 로그인, 자원 생성, 권한/로깅 변경은 수행하지 않았다. UI·수집기·파서·탐지 코드도 변경하지 않는다.

## 1. 용도와 적용 범위

[Stratus Red Team](https://stratus-red-team.cloud/)은 실제 클라우드 환경에서 개별 공격 기법을 재현하여 탐지 규칙을 검증하는 도구다. 로그 수집기, SIEM, 또는 Windows/Linux의 모든 호스트 로그를 수집하는 에이전트가 아니다. 기법에는 ATT&CK 매핑이 제공되지만 이것이 Cloud SOC의 탐지 지원 범위를 의미하지는 않는다.

검토 시점 공식 플랫폼 목록은 AWS, Azure, GCP, Kubernetes, Amazon EKS, Entra ID다. **OCI는 목록에 없다.** 기존 OCI 환경에 그대로 실행 가능한 도구라고 가정하지 않는다. OCI에서는 공격 의도와 검증 방법을 참고하되 실제 API, Audit 필드, 권한과 탐지 조건을 별도로 설계해야 한다. [공식 지원 플랫폼](https://stratus-red-team.cloud/attack-techniques/supported-platforms/)

| 자료 | Cloud SOC에서의 활용 제안 | 검증의 한계 |
| --- | --- | --- |
| 앞서 검토한 Security Datasets S3 자료 | 이미 기록된 로그로 파싱·시간 흐름·원문 추적을 오프라인 검증 | 현재 환경의 실제 수집 성공을 증명하지 않음 |
| Stratus 기법 문서와 공개 실행 로그 | 기대 API 이벤트, 조사할 필드, ATT&CK 및 탐지 조건을 정리 | 공개 예시와 실제 환경의 형식/버전/값이 다를 수 있음 |
| 향후 승인된 Stratus 실습 실행 | 격리 환경에서 이벤트 생성부터 수집·탐지·조사 연결까지 검증 | 도구 실행 성공만으로 로그 수집/탐지 성공을 판정하지 않음 |

Security Datasets 확인 결과는 [AWS S3 참고 검토](reference_securitydatasets_aws_s3.md)를 따른다. 현재 Phase A에서는 문서와 UI 계약 참고까지만 하고, 실습 실행은 자동 착수하지 않는다.

## 2. 문서 검토 후보

아래는 운영 실행 권장이 아니라 향후 탐지 설계/오프라인 검증 후보다. API 호출 자체와 악성 판정, 요청과 실제 상태 변경을 구분한다.

| 후보 | 기대 CloudTrail 이벤트 | Cloud SOC 조사 관점 |
| --- | --- | --- |
| [IAM 사용자 접근 키 생성](https://stratus-red-team.cloud/attack-techniques/AWS/aws.persistence.iam-backdoor-user/) | `CreateAccessKey` | 생성 주체와 대상 사용자, 승인된 작업 여부, 후속 사용을 확인. 단일 키 생성만으로 악성 확정하지 않음 |
| [보안 그룹의 SSH 외부 개방](https://stratus-red-team.cloud/attack-techniques/AWS/aws.exfiltration.ec2-security-group-open-port-22-ingress/) | `AuthorizeSecurityGroupIngress` | 대상 그룹, 프로토콜, 포트 범위, 허용 CIDR, 변경 주체/성공 여부를 확인. 단순 API 이름만으로 외부 개방을 판정하지 않음 |
| [CloudTrail 기록 중단](https://stratus-red-team.cloud/attack-techniques/AWS/aws.defense-evasion.cloudtrail-stop/) | `StopLogging` | 대상 trail, 호출 주체, 오류 여부와 후속 수집 상태를 확인. 보안 경보와 수집 건강도를 별도로 표시 |

위 공식 기법 페이지는 익명화된 실행 로그도 제공한다. 우선 공개 로그로 구조와 탐지 조건을 검토하는 편이 현재 단계에 맞다. 로그를 재배포하거나 테스트 fixture로 편입하기 전 라이선스·출처와 식별자 처리 방식을 확인한다. 이번에는 페이지의 예시를 읽었을 뿐 fixture로 복사하거나 실제 실행 결과를 생성하지 않았다.

### 공개 예시를 그대로 정답으로 쓰지 않기

- 확인한 Stratus 예시에는 `eventTime`이 있다. 앞서 검토한 Security Datasets 파일은 `@timestamp`를 사용했으므로 입력 프로필과 이벤트 시각 출처를 구분한다.
- 익명화로 변형된 리전/IP/CIDR 등을 실제 AWS 환경의 유효 값으로 간주하지 않는다. 원문을 보존하고 유효성 검사 실패와 의미 정규화를 분리한다. 기법 설명과 예시 값의 차이도 기록한다.
- `stratus-red-team` 사용자 에이전트나 테스트 자원 이름은 테스트 상관분석 보조 정보이지 운영 탐지의 필수 조건이 아니다. 도구 이름이 없는 동일 행위도 검증해야 한다.
- 도구가 자원을 준비하거나 정리하면서 남긴 이벤트를 핵심 공격 행위의 탐지 근거와 섞지 않는다. 정상 변경 작업과 권한 거부 사례도 따로 포함해야 오탐/누락을 평가할 수 있다.

## 3. Cloud SOC 검증 계약 제안

향후 실데이터 검증은 **이벤트 생성 → 원문 수집 → 필드 정규화 → 규칙 평가 → 경보 → 조사 화면의 같은 원문 참조**를 단계별로 확인한다. 아래 항목은 프로젝트 제안이며 현재 구현된 기능이 아니다.

- 실행 기록: 테스트 ID, 도구 버전, 기법 ID, 계정/리전/대상 자원, 시작/종료 시각, 준비·재현·정리 단계를 기록한다. ATT&CK 매핑의 출처/버전도 남긴다.
- 수집 확인: 실제 이벤트 ID와 소스, 이벤트 시각/수집 시각, 원문 참조를 연결한다. 클라우드 로그 전달 지연을 고려해 기한 내 미도착과 규칙 미탐지를 분리한다.
- 파싱 확인: 주체/계정/행위/자원과 소스별 필드를 대조한다. 결측·비-IP 출발지·오류 결과를 버리지 않는다.
- 탐지 확인: 예상 규칙, 실제 경보, 정확한 근거 이벤트를 비교한다. 이벤트 생성 실패, 수집 실패, 파싱 실패, 규칙 미일치를 각각 판정한다.
- 화면 확인: 통합 로그에서 해당 원문, 관제 현황에서 조사할 업무, 사건 조사에서 탐지 이유와 근거를 연결한다. 모의 실행/공개 재생 자료임을 표시한다.
- 탐지 범위: 문서 참고, 데이터셋 검증, 실수집 검증, 탐지 검증을 구분한다. 특정 기법 하나를 통과해도 해당 ATT&CK 기법 전체 또는 모든 클라우드를 탐지한다고 표시하지 않는다.

## 4. 실제 실행 전 조건

공식 FAQ는 샌드박스 계정/클러스터 사용을 전제로 하며 넓은 권한을 권장한다. 이를 현재 환경에 관리자 권한을 부여하라는 지시로 해석하지 않는다. 도구 버전별 필요 권한과 영향 범위를 검토하고, 별도 승인된 격리 실습 환경에서만 계획한다. [공식 FAQ](https://stratus-red-team.cloud/faq/)

자원 생성, 접근 키 발급, 방화벽 변경, 로그 중단 등이 실제 상태에 영향을 주며 비용이 발생할 수 있다. 대상 계정/리전·테스트 자원·비용 상한·권한·기록 수집 경로·복구 책임을 실행 전에 확정한다. 특히 기록 중단 실험은 운영 감사 경로를 대상으로 하지 않고 관측 경로를 별도로 검토한다.

준비, 공격 재현, 정리는 서로 구분된 단계다. 기본 재현 동작에 정리가 항상 포함된다고 가정하지 않으며, 실행 실패 후에도 생성 자원·접근 키·보안 설정의 잔여 상태와 비용을 확인해야 한다. [공식 사용 흐름](https://stratus-red-team.cloud/user-guide/usage/)

이번 작업은 문서 검토뿐이다. 도구 설치, 공격 명령 실행, 실제 클라우드 검증 또는 자동화 등록은 하지 않았다.
