## 검색·페이지·모바일 결과

- 양 OS × Filebeat/Packetbeat 4조합에 호스트 완전 일치와 해당 VM IP를 함께 검색했다. 모든 반환 row의 OS·수집기·호스트·수집기 ID가 일치했다. 직접 지정 KST 입력의 시작/종료가 UTC API 조건과 일치하고 종료 미포함을 확인했다. 로그 기준 시각 조회도 실제 Linux 문서의 `@timestamp` 범위와 일치했다.
- Windows 실제 네트워크 문서 50건 × 3페이지, 각 스냅샷에서 참조 150개·중복 0. 두 차례 스냅샷 모두 ES `mget`으로 150개 참조의 존재·필터·수신 시각 내림차순을 독립 대조했다. 서로 다른 스냅샷 사이의 고유 300건을 뜻하지 않는다. 다음 요청은 커서 하나만 보내고 이전/방문한 다음 페이지는 동일 참조의 메모리 캐시를 표시했다.
- 1440×1000 데스크톱과 390×844 모바일을 실제 Edge에서 검증했다. 모바일 4조합 모두 문서 폭 390, 표의 스크롤 영역 폭 364/내용 폭 2550, 상세 폭 370 및 내부 369/369로 페이지·상세 가로 넘침 없음. 표는 의도한 내부 수평 스크롤을 사용한다. 실제 목록·IP 열을 스크롤한 화면도 보존했다.
- 실제 존재하지 않는 호스트 검색은 빈 결과·다음 비활성으로 표시했다. 새로고침에서 현재 조건의 첫 페이지가 다시 표시됐다. 모바일에서 Linux network 참조가 `IAqUBqEBYPLrp-rq1u64`(11:03:00.024605Z) → `WwqVBqEBYPLrp-rqJO7S`(11:03:20.018017Z)로 바뀌고 새 receipt와 DOM이 일치했다. 같은 인덱스의 두 문서를 ES에서 독립 재조회했다.
- 전체 원문은 `raw_access=restricted`. 캡처한 실제 응답에 메시지·`event.original`·전체 `event_data`·명령행·토큰/키가 없고 브라우저 local/session storage가 비어 있었다. P2-01을 우회하는 옵션이나 원문 내보내기를 만들지 않았다.

## 합성 안전 표시와 시험 도구 보완

실제 포털 페이지의 브라우저 메모리에서만 로그 응답을 합성으로 바꿨다. ES에 유해 문서나 오류를 쓰거나 실제 서비스를 중단하지 않았다. HTML/스크립트처럼 보이는 호스트·문서 ID·공급자·행위·사용자 문자열이 목록과 상세에서 문자 그대로 표시됐고, `img/script` 노드 생성·시험 실행 표식 변경 없음. 합성 401/410/503은 안전한 오류 안내, 이전 row/상세/다음 버튼 초기화를 확인했다. 마지막에는 합성 응답을 해제하고 실제 검색 성공을 다시 확인했다. 브라우저 Runtime 오류 0.

독립 조회 도구의 첫 시도는 Docker에 전달되지 않는 추가 FD 때문에 실패했다. 표준 입력 전달로 보완했다. 이후 ARP의 없는 포트를 문자열 `None`으로 기대한 도구 오류를 발견해 실제 화면의 `미관측`과 대조하도록 고쳤고, TCP 표본을 추가 선정해 두 표본 모두 검증했다. 새 CDP 연결은 화면 크기를 다시 지정해야 하므로 새로고침 도구에서도 390px를 명시하고 화면을 재확인했다. 제품 수정·재배포가 필요한 오류는 발견하지 않았다.
