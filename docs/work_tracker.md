# Cloud SOC 작업 목록

최종 갱신: 2026-09-22 (KST). 최초 확인 기준: `main`의 `a7893bf`.

목표: 실제 에이전트 데이터로 로그 조회, 보안 활동 조사, 탐지와 사건 처리를 수행하는 Mini SIEM을 만든다. 기존 디자인과 수집기를 활용하고, 샘플을 실제 데이터처럼 표시하지 않는다.

## 상태와 완료 규칙

- `[ ] 대기`: 아직 시작하지 않은 작업.
- `[ ] 진행 중`: 실제 조사·구현·검증을 진행하는 작업. 동시에 진행하는 주요 구현은 하나를 기본으로 한다.
- `[ ] 확인 필요`: 서버 접근, 사용자 결정, 실제 수신 증거 등 외부 확인이 남은 작업. 필요한 정보를 해당 항목에 기록한다.
- `[x] 완료`: 해당 항목의 완료 기준을 충족하고, 검증 결과와 근거를 아래 이력에 기록한 작업.
- 코드 구현, 테스트, 서버 배포, 실제 수신 확인을 구분한다. 코드가 존재하거나 테스트가 통과했다는 이유로 배포·실제 수신 항목까지 완료 처리하지 않는다.
- 작업 시작 시 ID와 상태를 갱신하고, 종료 시 테스트 결과·남은 제약·관련 파일 또는 커밋을 기록한다. 실패하거나 일부만 끝난 항목은 체크하지 않는다.
- 비밀번호·API 키·개인키·실제 민감 로그는 이 목록이나 검증 기록에 넣지 않는다. 호스트명 등 식별정보도 필요한 최소한만 남긴다.
- 커밋·푸시는 별도 요청에 따라 수행한다. 완료 표시 자체가 원격 저장소나 AWS 서버 반영을 뜻하지 않는다.

## P2. 수집 확대 전 보호와 품질

2026-09-22 범위 보완: P1-02/03에서는 인증된 메타데이터 목록·제한된 상세부터 연결한다. 자유 텍스트(`message`, `event.original` 등)와 전체 원문 노출은 P2-01의 보호 정책 검증 전 기본 차단한다. 원문 검증 기준을 삭제하지 않으며, 제한된 상세를 전체 원문 조회 완료로 표시하지 않는다.

- [ ] P2-01 확인 필요: 민감정보 취급과 조회 권한을 보강한다. 완료 기준: 파일 본문·개인키·비밀번호 수집 제외, 로그/명령 인자/URL에 섞인 비밀정보의 마스킹 지점과 원문 보존 정책 확정, 민감 필드가 API·화면·오류·내보내기에 노출되지 않는 테스트 통과. 다중 사용자 도입 전 역할별 접근 통제를 검증한다. 로컬 보호 처리는 P2C-01 완료. 실제 소스별 개인정보 검토, 과거 ES 원문 취급/보존 승인, 다중 사용자 역할·원문 감사는 남음. 전체 원문·내보내기는 계속 차단.
- [ ] P2-02 확인 필요: 저장량·보존·백업 정책을 구현한다. 완료 기준: 예상 수집량 측정, 승인된 보존 기간과 디스크 임계값 정의, 격리 환경에서 삭제/보존 동작 및 스냅샷 복구 시험. 운영 로그 삭제 정책은 승인 없이 적용하지 않는다. 조회 도구와 격리 ILM·복구 시험은 P2C-02 완료. 실제 유입량 표본, 보존 기간/임계값 승인, 운영 백업 저장소·복원 시험은 남음.
- [ ] P2-03 대기(부분 구현): 소스별 수집 상태를 중앙에 보고한다. 완료 기준: 로컬 `discovery-report.json`의 선택/제외/접근 실패를 인증된 경로로 전달하고, 보고 시각·지연·전송 오류·큐 상태를 보여준다. 선택된 소스를 실제 수신 성공으로 간주하지 않는다. P2C-03의 보고·화면은 완료. 큐/전송 오류는 미측정이며 후속 계측 구현과 실제 OS 수신 검증이 필요.
- [ ] P2-04 대기(부분 구현): 수집 경로·제외 정책과 기존 에이전트 업데이트 절차를 만든다. 완료 기준: 기본 경로 밖 앱 로그를 승인된 디렉터리 단위로 추가하고 정책 버전·변경 이력을 남기며, 기존 registry·미전송 큐·키를 보존한 갱신/복구 테스트 통과. 임의 원격 명령 실행은 범위에서 제외한다. P2C-04는 정책 v1 지원 설치의 로컬 설정 갱신/복구만 완료. 구버전 전체 이행 도구와 실제 서비스·미전송 큐 보존 시험은 남음.
