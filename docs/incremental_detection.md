# 영속 증분 탐지와 장애 표시

2026-10-04 / P5-02. 코드와 모의 ES 시험 범위이며 실제 Elasticsearch·Docker·운영 배포 인수는 별도다.

## 동작

기본 CLI는 SQLite 영속 증분 모드다. 기존 전체 스냅샷은 `--snapshot`으로 명시 선택한다.
기존 AUTH-001의 조직/IP 구분, 10건/300초, cooldown 및 불변 경보 저장을 유지한다.

- 정규화 시각 `cloud_soc.normalized_at` 기준 5분 배치를 PIT/search_after로 완전히 읽는다.
- 발생 시각 기준 기본 15분 지연 버퍼 후 평가한다. 상태에는 미평가 이벤트, 그룹별 시간 창/cooldown, 중첩 조회 중복 ID가 저장된다.
- 조회는 15분 중첩한다. 이는 정규화 작업 시작 시각부터 실제 저장·검색 가능 시각까지 최대 15분 지연을 전제로 한다. 이 한계를 넘는 정규화/refresh 장애의 무손실은 보장하지 않으며 정규화 서비스 장애도 함께 감시해야 한다.
- 시간 창과 cooldown은 재시작 후 유지된다. SQLite BEGIN IMMEDIATE로 같은 상태 파일의 동시 처리자를 거부한다. 동일 소스에 서로 다른 상태 파일을 사용한 다중 탐지기는 지원하지 않는다.
- 경보를 create-only로 저장하고 상태 게시에 성공한 후 로컬 체크포인트를 커밋한다. 실패하면 체크포인트를 유지하며 같은 ID로 재시도한다. ES와 SQLite 간 분산 트랜잭션/정확히 한 번 처리 보장은 아니다.
- 확정한 발생 시각보다 오래된 새 이벤트는 재평가하지 않고 `late_total`에 기록한다. 원본은 보존된다. 개별 제외 이벤트 전용 저장소와 자동 backfill은 후속 과제다.
- 배치 조회/활성 상태 상한 초과, 불완전한 근거, 미래 시각 이상은 회차 실패다. 누적 전체 인덱스 크기는 조회 상한을 소비하지 않는다.

## 적용 순서

1. 기존 처리/탐지기를 중지하고 상태 파일과 ES Snapshot을 보호 백업한다.
2. 관리자 준비 단계에서 `cloud_soc.processing.setup.prepare()`를 다시 실행해 정규화 시각 및 상태 지표 매핑을 추가한다. 기존 `cloud_soc.detection.setup --prepare-processing`도 이 경로를 사용하지만 새 키를 발급하므로 이미 있는 키 파일을 덮어쓰지 않는다.
3. 변경된 normalizer를 사용한다. 기존 문서는 create-only이므로 자동으로 변경하지 않는다.
4. 시작 시각을 결정한다. 과거 정규화 시각 필드가 없는 문서가 있으면 최초 증분 실행은 실패한다. 과거 자료는 별도 스냅샷 평가/이행 검토 후, 이후 자료만 평가할 때 `--accept-legacy-exclusion`을 명시한다. 제외 건수는 저장되고 포털 경고에 표시된다. 기존 자료의 조용한 제외나 해시/근거를 바꾸는 자동 덮어쓰기는 하지 않는다.
5. 로컬 영속 상태 경로, UTC 시작 시각, 소스 endpoint를 고정해 실행한다.

```sh
python -m cloud_soc.detection --run \
  --es-url https://elasticsearch:9200 --ca-file /run/certs/ca.crt \
  --api-key-file /run/keys/detector.key \
  --state /data/runtime.sqlite --start 2026-10-04T00:00:00Z
```

위 시작 시각은 예시다. `--start` 이전 자료는 평가 범위 밖이며 업무상 승인된 시작점을 사용한다. 시작점/규칙/지연 정책/endpoint/과거 제외 정책이 바뀌면 기존 상태 사용을 거부한다. 새 상태를 만들기 전 재처리와 경보 중복 영향을 검토한다.

Compose는 `SOC_DETECTION_START`를 요구하고 `${SOC_STATE_DIR}/detection`을 `/data`에 영속 마운트한다. 과거 제외가 필요한 기존 환경은 별도 command override에 `--accept-legacy-exclusion`을 명시한다. Windows 상태 폴더 ACL과 Linux 디렉터리 0700/파일 0600을 적용한다. SQLite WAL/SHM도 함께 보호하고 온라인 백업 API 또는 탐지기 중지 후 일관된 백업을 사용한다.

## 장애 알림

운영 화면은 탐지 실패, 5분 초과 상태 미갱신, 20분 초과 체크포인트 지연, 지연/과거 제외 경고를 표시한다. 마지막 성공 시각은 실패 후에도 남긴다. 장애 상태는 보안 공격 경보로 저장하지 않는다.

이 단계의 알림은 포털 상태 표시/API이며 이메일·메신저·SMS 발송은 포함하지 않는다. 포털에 접속하지 않아도 통지해야 하는 운영 환경은 독립 감시가 상태 API를 검사하도록 연결해야 한다. ES 전체 장애 시 탐지기가 상태를 쓰지 못하므로 포털 조회 실패와 외부 가용성 감시가 필요하다.
