## 발견·수정

초기 실제 실패 9회는 중앙 원본 18개/PAM 기록 18개를 만들었지만 SSH 실패로 정규화되지 않았다. 실제 입력은 journald 본문과 시간대가 있는 ISO auth.log였고 기존 SSH 파서는 RFC3164를 처리했다. 두 형식용 `linux_ssh_v2`와 실제 처리기의 journald 프로세스/PID 읽기를 추가했다. 본문·명령 인자·비밀 값을 정규화 결과나 작업 목록에 복사하지 않는다.

첫 중복 비교는 같은 관측의 밀리초 시각 일치를 기대했지만 실제 rsyslog 경로가 약 1ms 늦는 사례를 발견했다. 판정 유예가 끝나기 전에 탐지기만 중지하고 상태를 보존했다. 동일 조직/호스트·PID·IP/포트·사용자·행위/결과/인증 방식과 서로 다른 두 수집 경로·5ms 이내 차이를 함께 확인하도록 보완했다. 실제 수신 20개/18개의 10쌍/9쌍을 후보 이미지에서 네트워크 없이 검증한 뒤 재개했다. 재개 전 저장된 경보는 0개였고 잘못된 경보를 지우거나 문서를 덮어쓰지 않았다. 두 경로의 원본 시각·문서는 모두 유지한다.

## 한계·다음 단계

- 네 에이전트 수집 키와 정규화/탐지 서비스 키는 실제 ES에서 유효·미폐기·미만료를 확인했다. 기존 수집 키를 교체하지 않았다.
- 기본 15분 유예 때문에 이번 경보는 마지막 실패 수신 직후 표시되지 않았다. 경보 시각과 실제 생성/화면 확인 시각을 구분한다.
- Windows 4625에는 SSH를 확정할 `network.protocol`이 없어 AUTH-001에서 `missing_condition_fields`로 기록했다. 기존 1건과 이번 1건의 평가 제외를 안전 판정으로 바꾸지 않는다. Windows 전체 인증 위험 탐지 인수가 아니다.
- PAM 원본 수신은 확인했지만 범용 PAM 해석·선택 ATTACK/AWS 프로필·일반 역할/추가 조직은 전체 인수가 남는다. 상위 P3-01/P5-03/P5-05 체크는 유지한다.
- 사건 생성·메모/판정·재조회·재시작 보존은 아직 수행하지 않았다. 다음 P6/P7 시연은 이번 실제 경보를 사용한다.
- 같은 VM 보호 백업이며 독립 저장소/보존 정책 P2-02는 보류다. 새 패치 커밋·푸시는 아직 하지 않았다. 발표 때 현재 24시간 범위에서 시험 기록이 벗어나면 검증된 7일 조회 또는 직전 통제 시험을 사용한다.
