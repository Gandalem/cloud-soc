## 2026-10-13 개인 대시보드 확장 (로컬 구현·검증)

개인 화면을 최대 20개 생성·복제·이름 변경·삭제 확인·기본 지정·즐겨찾기로 관리한다. 통합 보안 현황, 공격 탐지·사건 조사, 클라우드 감사·IAM 현황, 에이전트·수집 현황의 4개 템플릿과 빈 화면을 제공한다. 홈과 기존 `/api/dashboard`는 그대로 유지한다. 기존 설정 행은 조회로 이행/수정하지 않으며 ‘기존 화면 복제·편집’을 명시적으로 선택하면 새 개인 화면을 만든다. 아래 ‘계정당 한 구성’ 설명은 확장 전 이력이다.

`/api/dashboards`는 인증된 계정의 컬렉션과 카탈로그·템플릿을 조회하고, POST의 고정 작업(create/save/rename/duplicate/delete/default/favorite)으로 설정을 변경한다. 계정·조직·ES 쿼리·외부 주소를 입력할 수 없다. 동일 출처·JSON·X-Cloud-SOC·세션 CSRF와 기존 역할/조직 범위를 적용한다. 조회자는 자기 표시 구성만 저장하며 사건·원문·에이전트·전역 진단 권한은 늘어나지 않는다.

위젯 유형과 인스턴스 ID를 분리해 같은 유형을 여러 개 추가할 수 있다. 라이브러리 검색/분류, 독립 표시 이름·기간·차트·표시 건수·정렬·경보 표본 필터·강조색, 12열 배치와 ¼/½/전체 너비·높이를 지원한다. 포인터 이동/크기 핸들, Alt+위/아래 방향키와 이동 버튼, 모바일 한 열·패널 전환을 제공한다. 최대 24개·허용 그리드·비겹침·설정 허용 목록은 서버에서도 검사한다.

편집은 미리보기이며 저장·취소·마지막 저장 복원·템플릿 초기화·30단계 Undo가 있다. 템플릿 초기화도 명시적 저장 전에는 DB를 바꾸지 않는다. 실패/409에서는 편집을 유지하고, 서버 구성 재조회는 확인 후 현재 편집을 취소한다. 다른 화면으로 전환하거나 떠날 때 미저장 변경을 알린다. 컬렉션 revision 하나로 모든 개인 화면의 동시 변경을 검출한다. 이는 각 화면의 독립 병합 기능이 아니다.

같은 소스/기간의 데이터 요청을 한 번만 보내고 최대 3개씩 조회한다. 갱신·페이지 이탈·화면 숨김에서 이전 요청을 취소하고 오래된 응답은 버린다. 60초 자동 갱신과 수동 새로고침을 제공한다. 설정/로그/권한/자격 증명을 브라우저 저장소에 복제하지 않는다. 전역 테마만 기존 허용 값으로 유지한다.

31개 후보 중 관리자 26개, 분석가/조회자 23개가 기존 API에 연결된다. 경보·수신·처리 추이는 기간 전체 집계이며, 심각도/규칙/출발지/클라우드·소스 분포는 최신 최대 50건 표본이다. 클라우드 계정은 관측 계정이며 등록 계정 총수가 아니다. 경보 시간순 목록과 동일 경보의 출발지 관계는 공격 인과관계·동일 세션·공격 성공의 증명이 아니다. 위치·오프라인·성공률·계정 위험 점수·근거 시퀀스 위젯은 사용 불가 사유를 표시한다.

저장은 기존 `dashboards.sqlite`에 추가한 `dashboard_collections(actor, revision, body)`를 사용한다. 기존 `dashboards` 테이블·행·revision은 유지한다. 백업 도구는 새 테이블이 있으면 format 4를 사용하고 format 1/2/3의 검증·새 경로 복원을 유지한다. 구형 백업 도구는 새 DB 스키마를 백업하지 못하므로 이번 소스와 같은 버전의 도구가 필요하다.

자세한 파일·검증 명령·결과·위젯별 데이터/한계는 [확장 인수 기록](dashboard_platform_validation_20261013.md)을 따른다. 로컬 합성/임시 SQLite·앱 재생성 범위이며 실제 서버 배포·운영 계정/데이터 인수·키 갱신은 하지 않았다.

## 2026-10-12 고객 화면 정리

홈 경보는 8건을 먼저 보여주고 펼치면 최신 최대 50건을 조회한다. 정확한 근거는 경보의 ‘근거 보기’로, 전체 사건 업무는 ‘사건 조사’로 연결한다. 전체 경보 페이지 탐색은 현재 미지원이며 50건 제한을 표시한다. 미종결 사건 수는 목록의 25건 표본이 아니라 동일 권한의 열린 사건 쿼리 전체 집계이며 조회 기간과 별도다.

기존 `pipeline`/`processing` 위젯 설정은 저장소에서 읽고 취소할 수 있으며 조회로 자동 수정하지 않는다. 렌더링/편집에서는 숨기고 명시적 저장 때만 현재 선택을 반영한다. 옛 구성에 기술 위젯만 있다면 위젯 선택 안내를 제공하고 기본 구성으로 복구할 수 있다.

분석 중단·지연·미확인 경고는 위젯 선택과 무관하게 한 번 표시한다. 상세 진단 링크나 정상 반복 이력은 고객 메뉴에 넣지 않는다. 기존 역할별 직접 진단 권한은 확대하거나 축소하지 않았다. 이번 변경도 로컬 소스이며 실제 배포는 별도다.

후속 정리의 관련 Python 58/7 subtests·화면 123·Chrome 18개·링크/보존 결과는 [정리 검증](archive/validation/customer_cleanup_20261012.md)에 있다. 기존 검증 이력은 그대로 유지하며 새 UI 실제 배포는 남는다.

## 2026-10-12 전역 테마 후속

홈의 ‘화면’ 드롭다운을 제거하고 모든 업무 화면의 공통 헤더에서 현재 화면 이름 옆 버튼으로 다크/화이트 모드를 전환한다. 버튼은 전환할 모드를 표시하며 선택·hover·키보드 focus의 메뉴 대비를 함께 유지한다. 로그 필터/표/상세 패널, 사건 목록/상세/폼과 에이전트 화면도 공통 팔레트를 사용한다.

브라우저에는 `cloud-soc.theme`의 허용된 두 값만 저장한다. 명시적 전역 선택이 없을 때만 기존 개인 구성의 테마를 받아들이며 저장/취소·서버 응답이 현재 전역 선택을 덮지 않는다. 테마는 같은 브라우저의 전 화면 표시 설정이며 다른 브라우저 자동 동기화가 아니다. 저장이 차단된 브라우저에서도 현재 페이지 전환은 동작하지만 새로고침 후 유지에는 저장 허용이 필요하다. 역할·조직·API 쿼리·로그인 비밀 값을 저장하거나 권한을 늘리지 않는다.

지정 포털 실제 후속 반영·검증 결과는 [테마 보고서](archive/validation/theme_validation_20261012.md)에 있다. UI 127·합성 42/실제 18개의 검증과 단계별 제한을 구분한다.
