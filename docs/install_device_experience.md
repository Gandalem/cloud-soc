# 설치·배포·장치 관리 개선

## 범위와 기준

2026-10-23 승인 최종안의 1~3차를 구현한다. 기준 main은 34c2139이고 작업 브랜치는 `codex/install-device-experience`, 작업 경로는 `work/cloud-soc-main`이다. 원본 `D:/cloud-soc`와 상용화 PoC를 수정하거나 가져오지 않는다.

사용자 지시대로 구현 작성100% 전에 테스트·린트·빌드·실행 검사를 하지 않는다. 작성 후 필수 실패 경계·권한·상태 보존·격리 흐름을 한 번에 확인한다. 원격 배포·운영 장치·기존 키·재부팅·이관·커밋·푸시·병합은 제외한다.

2026-10-25 최신 사용자 요청으로 이 구현과 후속 문서의 현재 작업 브랜치 커밋·푸시만 승인됐다. 위 구현 당시 제외 기록은 보존하며, main 병합·운영 배포·추가 검사 승인을 의미하지 않는다.

## 사용자 흐름

기본 진입점은 `devices.html`이다. 이름·조직·OS·수집 목적을 선택하면 장치와 설치 요청을 먼저 저장한다. 같은 생성 요청을 재시도하면 같은 장치로 연결한다. 등록 정보를 준비한 뒤 ZIP을 다운로드한다.

ZIP을 모두 푼 후:

- Linux: `sudo sh soc-agent install` 또는 `sudo sh soc-agent` 메뉴. `sh soc-agent --help`.
- Windows: `Start.cmd` 실행. `Start.cmd help`. 필요 시 관리자 권한을 요청한다. 실행 정책은 변경하거나 우회하지 않는다.
- 네트워크 수집은 실제 NIC 선택이 필요하며, Windows의 승인된 Npcap 설치를 자동으로 대신하지 않는다.

장치 상세에서 최초 등록 시험 수신, 일반 로그 수신 조회, 용도별 자격 증명, 접근 차단, 진단 파일을 제공한다. 최초 시험 수신을 일반 로그·분석·경보 생성 성공으로 확대하지 않는다. 장치 heartbeat와 분석 상태는 현재 직접 관측하지 않았으면 unknown이다.

기존 `agents.html`·수동 API는 보존한다. 새 장치의 패키지에는 수동 키 발급·별도 토큰 발급·패키지 삭제를 허용하지 않는다. 기존 키를 이름/IP로 자동 연결하지 않는다. 기존 장치 인수는 별도 신원 확인 계약이 필요한 후속이다.

## 공통 프로그램과 장치 설정

서버가 실행 파일을 빌드하지 않는다. 기존 허용 파일 목록으로 만든 원본 패키지에서 정적 도구만 `runtime.zip`으로 묶는다. 고정 zip timestamp와 정렬을 사용해 같은 OS/수집 옵션/소스의 runtime은 장치가 달라도 byte-identical이다.

장치별 `package.json`·공개 CA·collection profile·원본 SHA256SUMS·단기 registration은 별도다. 원본 패키지 SHA-256은 기존 enrollment API 계약을 유지한다. outer ZIP과 runtime hash는 별개다. 레거시 파일별 checksum은 손상 확인이며, 미서명 다운로드 자체의 신뢰나 호스트 관리자 침해 방어를 주장하지 않는다.

Linux는 root 전용 `/var/lib/cloud-soc-bundles/<device-id>`로, Windows는 관리자/SYSTEM 전용 `%ProgramData%/Cloud-SOC-Bundles/<device-id>`로 전달한다. 경로 이탈·중복 ZIP 항목·크기 초과·링크·기존 버전/설정 불일치를 거부한다. 기존 프로그램을 자동 교체하지 않는다.

등록 시 장기 수집 키는 기존 TLS API와 keystore stdin 경로를 사용한다. 사용자 복사나 argv 전달이 필요 없다. Linux 재시도 식별자는 보호된 파일, Windows 재시도 식별자는 DPAPI 보호 파일에 보관한다. Windows 파일은 암호화한 관리자 계정으로 복구해야 한다. 장치 관리와 수집용 자격 증명을 같은 것으로 취급하지 않는다.

## 영속 상태와 재시도

기존 packages.sqlite3에 다음 선택적 완전한 schema 그룹을 추가한다.

- managed_devices: 안정적인 장치 ID, 표시 이름, 조직/OS/목적, 패키지, 상태/version.
- device_operations: actor와 요청 ID, action/fingerprint, 요청·완료·불확정 결과.
- device_transfers: 장치와 enrollment 연결, 단기 암호화 전달 정보.
- device_audit: 비밀값 없는 작업 감사.

요청 ID 재사용의 actor/action/body 차이는 충돌이다. 생성은 패키지와 장치를 같은 SQLite transaction에 저장한다. 발급 전 예약을 저장하고, 명시적 갱신이 진행 중 발급을 대체하면 version fence로 오래된 발급의 게시를 막는다. 결정적인 enrollment ID로 중단된 발급을 찾을 수 있다. 원격 성공과 로컬 저장 실패를 성공 처리하지 않는다.

재다운로드는 같은 unused/unexpired 등록 정보를 사용하며 수집 키를 새로 발급하지 않는다. 만료/분실은 명시적 갱신으로 처리한다. 이미 키를 전달한 issued/complete 세션은 신규 등록으로 덮어쓰지 않는다.

장기 키 원문은 이 상태에 저장하지 않는다. 단기 등록 전달만 Fernet으로 암호화해 재다운로드를 지원한다. `device-transfer.key`는 0600, 일반 조회/진단/백업에서 제외한다. 이 파일은 장기 키 재조회 금고가 아니다. 키가 없거나 decrypt 실패하면 명시적 갱신을 요구한다. 호스트/포털 관리자가 모두 침해된 경우까지 보호한다고 주장하지 않는다.

기존 백업 형식의 DB 집합은 유지하며 packages DB의 선택적 schema 그룹을 정확히 검사한다. 장치 metadata와 암호문은 백업되지만 전달 복호화 키는 제외된다. 복원 후 새 키로 암호문을 조용히 재사용하지 않는다. 원격 이름/조직/패키지와 폐기를 확인해 갱신한다. 운영 복원과 모든 rollback/사이트 손실은 이번 검사로 보장하지 않는다.

## 폐기·이력·삭제

사용 중/조치 필요/폐기 이력을 서버 측 검색·필터·페이지로 구분한다. 기존 last-500 API는 호환용으로 유지하고 새 화면은 전체 이력 검색용 API를 사용한다. 영구 삭제·자동 보관 만료는 아직 실행하지 않는다. 운영 보관 기간, 감사 요구, 참조 보존, 백업에서의 재등장을 합의한 후 별도 작업으로 구현한다.

장치 종료는 등록 예약과 정확한 소유자 범위의 키 이름·조직·패키지를 확인해 폐기한다. 원격 부분 실패나 로컬 저장 실패는 revocation_pending과 uncertain으로 남기며 같은 요청을 재시도한다. 키가 단순히 조회되지 않는 것을 폐기 성공으로 추측하지 않는다. 원격 폐기 응답·재조회로 확인한 이력만 완료로 처리한다.

로컬 stop/start는 인식된 서비스만 다룬다. uninstall은 소유 기록·고정 경로·링크·변경된 파일을 확인하고, 보존 또는 명시적 DELETE를 선택한다. 큐를 조용히 삭제하지 않는다. 보존 자료는 관리자 전용 retired 디렉터리로 이동하며 자동 복원/재수집을 보장하지 않는다. 전체 프로그램 삭제는 원본 로그/서버 로그/경보/무관한 Filebeat를 삭제하지 않는다.

로컬 프로그램 삭제와 서버 접근 차단은 별개다. 장치가 오프라인이거나 관리 경로가 없으면 포털에서 차단하고 장치에서 프로그램을 정리한다. 임의 원격 셸/자동 uninstall을 제공하지 않는다. 부분 로컬 삭제 실패의 자동 재개와 완료된 장치의 완전 자동 재설치는 후속이며, 불명확한 기존 상태는 보존·거부한다.

## 서버 도우미

저장소 루트에서 `sudo sh soc` 메뉴 또는 `sudo sh soc install|uninstall`, `sudo sh soc status`, `sh soc --help`를 사용한다.

환경 선택, 주소 후보, 공인/사설 주소 설명, 시간 동기화 확인을 제공한다. 기존 설치기가 실제 자원/포트/주소/소유 관계를 검사한 뒤 변경한다. 신규 설치만 자동 진행한다. 기존 상태가 있으면 기존 manage.py 복구/업그레이드 계약을 안내한다. 추측한 설치 단계에서 무조건 재개하지 않는다.

삭제는 기존 uninstall.py의 프로젝트/공유 여부 검사와 확인을 재사용한다. 프로그램만 삭제하는 기본 선택에서는 데이터/인증서를 보존한다. 완전 삭제는 추가 DELETE 확인이 필요하다. 공용 Docker 제거·global prune·Apache 삭제를 호출하지 않는다.

## 패키징 도구

- [NSIS 3.13](https://nsis.sourceforge.io/Download): 공통 Windows EXE recipe. [기본 zlib/libpng 및 모듈별 조건](https://nsis.sourceforge.io/Docs/AppendixI.html), zlib compressor 사용.
- [nFPM 2.48.0](https://github.com/goreleaser/nfpm/releases/tag/v2.48.0): Ubuntu DEB recipe, [MIT](https://github.com/goreleaser/nfpm/blob/main/LICENSE.md). 새 제품 runtime dependency는 추가하지 않는다.
- 기존 Filebeat/Packetbeat 9.5.2와 cryptography 의존성을 재사용한다. 도구 라이선스가 포함 구성 요소의 재배포 허가를 대신하지 않는다.

`deploy/agents/packaging/build.py`에 로컬 도구 경로와 출력 경로를 명시한다. 도구 버전이 다르면 거부하며 실행 파일을 다운로드하거나 장치에 설치하지 않는다. 서명은 별도 보호된 release 단계다. 빌드 출력은 unsigned이며 production signed release라고 표시하지 않는다. 공통 EXE/DEB 배포 서버 연결과 release 인증서는 준비 조건을 따로 기록한다.

## 후속 범위

자동 키 교체/장치 control channel, 대화형 코드 승인(RFC8628), 다중 배포, 공인 인증서 갱신, TUF 업데이트, 기존 장치의 신원 확인 인수, 감사 보관 기간별 정리, 기존 완료 설치의 자동 재설치/보존 큐 복원은 후속이다. 미지원 작업은 성공으로 처리하지 않는다.

비용 조건은 추가 Windows 구매 없이 가능한 환경을 우선 비교한다. 기존 WSL에서 Linux 개발 검사를 진행할 수 있으나 일반 Ubuntu VM의 부팅/네트워크 인수와 같다고 표시하지 않는다. Windows Sandbox는 현재 PC 에디션과 지원 여부를 먼저 확인하고, 새 시험 설치/삭제에 활용 가능한 범위만 수행한다. 종료 시 상태 초기화 등으로 장기 운영·복원·일반 VM 부팅 인수를 대신하지 않는다. 현재 PC의 실제 서비스 설치·변경은 자동으로 착수하지 않는다. 지속 보존이 필요한 Windows VM은 사용 권한과 환경이 준비됐을 때 별도로 진행한다.

### 실제 Elasticsearch·Filebeat 격리 연결 결과
