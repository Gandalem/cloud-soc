# Portal 사용

홈·개인 대시보드·통합 로그·사건·공통 화면 안내를 통합했다. 설치/수집은 [장치 설치](device_installation.md)와 [에이전트 운영](agent_management.md), 기능별 구현/인수 범위는 [현재 상태](project_status.md)를 따른다. 예전 상세 안내와 날짜별 화면 검증은 [보관 자료](archive/README.md)에 원본으로 남겼다.

<a id="navigation"></a>
## 화면 선택

| 화면 | 주소 | 용도 |
| --- | --- | --- |
| 홈 | `/index.html` | 최근 경보와 조사 진입 |
| 내 대시보드 | `/dashboard.html` | 개인 구성·위젯·조회 기간 |
| 통합 로그 | `/logs.html` | 조건 검색과 보호된 상세 |
| 사건 목록/상세 | `/cases.html`, `/workbench.html?case=...` | 사건 생성·담당·판정·메모 |
| 장치 | `/devices.html` | 설치 요청·receipt·일반 수신·접근 차단 |
| 운영 진단 | `/operations.html` 등 직접 경로 | 처리·탐지/제외·실행 보고 확인 |

표시 메뉴는 인증 계정의 페이지 권한을 따르며 서버 권한 검사를 대체하지 않는다. 로그/경보 조회 기간과 사건 생성 기간은 별도다. 오래된 경보는 기간을 늘려 찾고, 경보만으로 공격 성공이나 WAF 차단 성공을 확정하지 않는다.

<a id="dashboards"></a>
## 개인 대시보드

이름/화면을 선택하고 편집에서 위젯 추가·제거·크기/설정·배치를 바꾼다. 편집 결과는 미리보기이며 **구성 저장**을 눌러야 서버에 반영된다. 취소·마지막 저장 복원·템플릿 초기화·Undo를 제공하고 템플릿 초기화도 저장 전에는 DB를 바꾸지 않는다. 저장 실패/409 충돌은 편집을 유지하며 서버 구성을 다시 불러올 때 기존 편집 취소를 확인한다.

컬렉션 revision이 개인 화면 전체의 동시 변경을 검출한다. 설정/로그/자격 증명을 브라우저 storage에 복제하지 않고 테마 허용 값만 보관한다. 조회 실패·부분/미관측은 성공이나0건으로 바꾸지 않는다. 위젯의 표본·표시 상한·실제 기간 집계 범위는 [대시보드 계약](dashboard_capabilities.md)을 확인한다. cloud 관측 계정 수와 등록 계정 총수는 다르다.

<a id="movement"></a>
### 위치 이동

편집 중 제목/이동 버튼으로 클릭 배치를 시작하거나 제목을 끌어 착지 미리보기를 표시한다. 다른 위젯의 앞/뒤 또는 허용된 빈 격자에 놓고, 작은 화면에서는 앞/뒤 버튼을 사용한다. Esc·취소·포인터 유실은 배치를 바꾸지 않는다. Alt+위/아래와 키보드 배치 버튼도 지원하는 설계다.

미리보기만으로 저장하거나 기존 배치를 자동 압축하지 않는다. 선택 위젯과 겹치는 항목만 이동하며, 실제 배치 변경 하나가 Undo 단위다. 크기 조절은 별도다. DASHBOARD-MOVE-01은 구현/실습 정적 파일 반영 기록이 있고 **사용자 지시로 실제 드래그·모바일·저장 인수는 생략**했다. 이 사용 설명을 해당 검수의 통과 기록으로 해석하지 않는다.

<a id="logs"></a>
## 통합 로그와 근거

허용된 출처·조직·기간/IP 등의 조건으로 조회하고 같은 PIT 스냅샷의 다음 페이지를 탐색한다. 이전 페이지는 방문 캐시이며 새로고침은 현재 폼 조건으로 첫 페이지부터 새로 조회한다. 임의 페이지 이동/전체 본문 검색·내보내기를 제공한다고 가정하지 않는다. 상세 필드·기간·조회 한도는 [조회 계약](log_query_contract.md)을 따른다.

로그 시각은 @timestamp이고 실제 행위 시각과 다를 수 있다. 서버 수신 활동은 event.ingested로 별도 판단한다. 현재 페이지 문서 수·표본을 전체 공격 수로 해석하지 않는다. Windows SID/원본 이벤트 ID·지원/부분 해석을 구분하고 관측되지 않은 행위·성공/실패를 추측하지 않는다.

경보의 근거는 정확한 raw/normalized index·ID와 정규화 event_hash를 대조한다. 일치·내용 변경·참조 불일치·만료/누락·과거 해시 미기록을 구분한다. 정규화 내용 해시 확인은 원본 문서 전체의 독립 무결성 보장이 아니다. 주변 활동/시간순 목록을 일치 근거나 인과관계로 자동 편입하지 않는다.

보호된 원문 필드는 [접근 정책](log_access_policy.md)의 조직·권한·사유·감사 조건을 충족한 허용 필드만 표시한다. 전체 본문/명령 인자/알 수 없는 필드의 공개 기능이 아니다. 감사 저장 실패나 권한/검색 오류는 원문 공개/정상0건으로 처리하지 않는다.

<a id="cases"></a>
## 사건 조사

1. 경보 상세의 **사건 조사 / 등록**에서 제목·우선순위를 입력해 명시 생성한다. 단순 조회/사건 ID 없는 진입은 사건을 만들지 않는다.
2. 목록에서 상태·담당·우선순위·생성 기간·정렬로 찾고 제목을 눌러 조사한다. 목록/집계는 같은 필터를 쓰며 복귀 시 조건/페이지를 보존한다.
3. 연결 경보·근거를 확인하고 담당·상태·판정·메모를 저장한다. 같은 조직의 추가 경보 ID를 연결할 수 있고 한 경보는 한 사건에만 연결된다.
4. 종결에는 판정과 사유가 필요하다. 종결 건을 고치려면 사유와 함께 조사 중으로 재개하며 판정은 미검토로 돌아간다.

작성 주체는 인증에서 정하고 version/Idempotency-Key로 중복·동시 변경을 처리한다. 실패/409 때 입력을 유지한다. 공용 관리자 계정은 실제 사람을 구별하지 못하며, 메뉴가 보이는 것만으로 조직별 권한이 보장되지 않는다. 제목·메모에 비밀/개인정보를 넣지 않는다.

사건·메모·판정·변경 이력은 cases.sqlite에 저장하고 ES 원본/경보는 읽기 전용으로 사용한다. 호스트 관리자의 SQLite 변조까지 막는 감사 저장소가 아니므로 [백업](portal_backup.md)과 접근 통제가 필요하다. 저장 당시 경보 메타데이터와 현재 ES 조회·만료/오류를 구분한다. 사건 저장과 ES 조회는 분산 트랜잭션이 아니다.

## 공통 화면과 적용

헤더/사이드바는 prototype/shell.js·shell.css를 공유하며 역할별 페이지 목록을 따른다. 모바일 메뉴는 같은 탐색을 사용하고 Escape로 닫아 초점을 되돌린다. 앱 화면에 개발 진행률/미검증 약속을 넣지 않고 실제 사용자 동작·결과만 표시한다.

Portal 변경은 HTML 한 파일 대신 대응 JS/CSS와 이미지를 함께 반영한다. 설치기/DB 초기화를 다시 실행하지 말고 [공통 런타임 갱신](runtime_deployment.md)과 현재 상태의 백업/권한 검사를 따른다. 코드/문서 변경만으로 운영 반영을 주장하지 않는다. Kibana 대시보드 가져오기는 [별도 안내](kibana_setup.md)를 사용한다.
