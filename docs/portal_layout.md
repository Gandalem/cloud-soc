# 포털 공통 레이아웃

현재 상태(2026-10-12 후속): 새 홈/개인 화면·고객 메뉴 정리를 지정 VMware에 실제 보호 배포했고 기존 admin 비밀번호를 유지한 세션 로그인과 상단 로그아웃을 확인했다. 아래 옛 로컬 단계/미배포 설명은 당시 검증 이력이다. [실제 결과](archive/validation/dashboard_deployment_20261012.md)

운영 화면 11개는 `prototype/shell.js`의 헤더·사이드바와 `prototype/shell.css`를 공유한다. 로그인은 같은 색상과 폼 스타일을 사용하되 메뉴는 표시하지 않는다. 각 HTML에는 `app-shell` 자리와 공통 자산 참조만 둔다.

## 메뉴 변경

- 메뉴 이름·주소·그룹·순서는 `shell.js`의 `groups`에서 한 번만 변경한다.
- 보안 관제: 홈 대시보드 → 내 대시보드 → 통합 로그 → 사건 조사.
- 별도 관제 현황·운영 진단 메뉴는 고객 탐색에서 제외한다. 직접 운영 경로·API와 기존 권한은 유지한다.
- 에이전트: 에이전트 설치 파일 → 발급 키 관리 → 에이전트 수신 현황.
- 과거 로그 분석 이력은 운영자 직접 경로로만 보존한다.
- `/api/auth/me`가 알려준 접근 가능한 페이지로 공통 메뉴와 빠른 링크를 제한한다. 서버의 역할·조직 권한 검사를 대체하는 기능은 아니다. 인증 상태를 확인할 수 없으면 메뉴를 정상 권한으로 추정해 노출하지 않는다.
- 페이지별 메뉴 HTML이나 별도 모바일 메뉴를 다시 추가하지 않는다. 미구현 메뉴는 동작 가능한 기능처럼 표시하지 않는다.
- 페이지 본문의 업무별 안내와 버튼은 각 페이지에 유지한다. 공통 헤더는 서버 정상·수신 성공을 주장하지 않는다.

## 현재 위치와 모바일

주소 경로로 현재 메뉴를 표시한다. 루트는 홈 대시보드, `workbench.html`은 사건 조사다. `agents.html#keys`는 발급 키 관리 창을 열며 닫으면 설치 파일 메뉴로 복귀한다. 다른 화면에서도 같은 링크로 진입하고 새로고침할 수 있다. 키 원문이나 인증정보를 주소에 넣지 않는다.

700px 이하에서는 헤더의 메뉴 버튼으로 같은 사이드바를 펼친다. 키보드 Tab으로 메뉴에 접근하고 Escape로 닫아 버튼에 초점을 돌린다. 작은 화면에서도 메뉴가 누락되거나 이름이 바뀌지 않는다. 메뉴는 JavaScript로 렌더링되며 기존 데이터 조회도 JavaScript가 필요하다.

## 검증과 배포

`prototype/tests/shell.test.cjs`에서 공통 컴포넌트 참조·중복 제거·메뉴 순서·활성 상태를 검사한다. 키 관리 테스트는 직접 링크·닫기·재진입을 검사하고 포털 테스트는 공통 자산의 인증을 검사한다. UI 검증은 별도 합성 서버에서 하며 운영 배포나 실제 수신 증거를 대체하지 않는다.

서버 반영 시 HTML만 복사하지 말고 포털 이미지를 공통 JS/CSS와 함께 재빌드한다. 기존 배포 갱신 절차는 [사건 업무 가이드](incident_workflow.md)를 따른다.

## 화면 원칙

- 제목·주요 작업·목록을 먼저 배치한다. 홈은 경보와 사건 요약을 함께 보여준다.
- 안내는 필요한 위치에 한 번만 둔다. 집계 기준·문서 ID·규칙 버전·점수 계산·상세 통계는 펼쳐서 본다.
- 0건, 조회 실패, 미측정, 미수신을 구분한다. 오래된 목록을 최신 결과처럼 남기지 않는다.
- 키 폐기 영향, 메모 수정 불가, 개인정보 제한, 공격 성공 미확정은 짧게 표시한다.
- 로그인과 버튼·검색·폼을 같은 스타일로 맞춘다. 모바일 표는 내부에서 가로 스크롤한다.

로그인 전 필요한 자산은 `/login/styles.css`, `/login/agents.css`, `/login/mark.svg`만 별도 고정 경로로 제공한다. `/api/auth/config`는 로그인 방식(session/basic)만 반환한다. 세션 방식에서만 입력 폼을 제공하고 기존 Basic 서버에서는 브라우저 인증을 사용하는 포털 진입을 안내한다. 작동하지 않는 세션 폼을 표시하지 않는다.
일반 포털 파일과 데이터 API의 인증·권한·CSP는 유지한다.

## 2026-10-12 검증

UX-01은 `pack`의 로컬 화면 개선이다. 10개 페이지와 키 관리·사건 진입을 1440px/390px에서
26회 검사했고 주요 창 9종도 두 크기에서 확인했다. 설치 파일·시험 키·메모 작업은 임시 저장소,
세션 로그인은 실제 포털 코드, 로그·수집·탐지 응답은 합성 자료다. 운영 설치·수신·키 폐기 증명이 아니다.

재현: 기존 개발 시험 환경에서 `tests/preview_portal_ux.py` 실행 후 로컬 `/login`에 시험 계정으로 로그인한다.
CLI 브라우저 검증은 `tests/browser_portal_ux*.cjs`, 회귀는 `prototype/tests/ux.test.cjs`와 기존 UI 시험을 사용한다.
로그인 자산 제한은 `tests/test_portal.py`, 기존 조직·권한 회귀는 `tests/test_integration_security.py`에 있다.
서버 배포는 별도 요청 후 진행한다.

## 2026-10-12 고객용 후속 개선

분석 중단·지연·미확인 때 짧은 경고를 표시한다. 정상 반복 실행은 고객 화면에서 숨기고, 홈/개인 화면에는 위젯과 무관한 경고를 한 번만 표시한다. 앞단 로그 해석 실패·지연·미시작·미확인을 탐지기의 반복 성공으로 덮지 않는다. 관제 메인의 저장된 경보 수와 전체 분석 완료 여부를 구분하고 분석 진단에서 완료 위치·최종 실행 상태·누락 사유를 확인한다.

실행 이력은 같은 run/rule의 최종 단계를 조회해 한 번만 표시하며 페이지 경계를 넘어선 완료도 대조한다. 새 입력 없는 완료 실행은 접은 요약/시각 목록으로 유지하고 실패·최종 저장 미확인·누락된 계측은 숨기지 않는다. 단계별 감사 원본은 삭제하지 않으며 API의 기본 기록 조회도 유지한다. 상세 `view=summary`는 전용 고정 인덱스의 단계 ID만 제한된 mget으로 대조한다.

정상·분석 중단·적체·빈 결과·503·두 로그인 방식·조회 전용 권한을 1440/390px의 실제 Chrome 격리 프로필에서 검증했다. 고객용 후속 코드/미적용 이미지와 앞선 UX-01/운영 배포 이력은 [검증 보고서](archive/validation/customer_readiness_20261012.md)에 구분한다.

## 2026-10-12 홈·개인 대시보드 후속

홈과 내 대시보드의 위젯·기간·테마, 계정별 저장·권한·재시작·브라우저 검증은 [대시보드 가이드](dashboards.md)에 있다. 이전 관제의 고객 메뉴는 제거하고 운영 직접 경로 operations.html로 보존하며 기존 사례·완료 이력과 합성 검증을 유지한다. 신규 화면은 실제 시험 서버에 아직 배포하지 않았다.
## 공통 테마 버튼

`theme.js`는 스타일 로드 전에 검증된 화면 테마만 적용하고 `theme.css`는 업무 화면 CSS 다음에 공통 팔레트/메뉴·표·폼·상세 대비를 적용한다. 현재 화면 이름 옆 버튼은 양 모드에서 동일 위치이며 키보드로 조작할 수 있다. 모든 페이지와 로그인에 고정 테마 자산을 사용한다. 로그인 전 공개 범위에는 테마 JS/CSS만 추가하며 포털/API 인증은 유지한다. 상세: [전역 테마](dashboards.md#2026-10-12-전역-테마-후속)
