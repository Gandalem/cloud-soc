# 포털 공통 레이아웃

운영 화면 7개는 `prototype/shell.js`의 헤더·사이드바와 `prototype/shell.css`의 반응형 레이아웃을 공유한다. 각 HTML에는 `app-shell` 자리와 공통 자산 참조만 둔다. 기존 정적 미리보기와 인증된 포털 모두 같은 파일을 사용하며 새 프레임워크나 API는 추가하지 않는다.

## 메뉴 변경

- 메뉴 이름·주소·그룹·순서는 `shell.js`의 `groups`에서 한 번만 변경한다.
- 보안 관제: 관제 현황 → 통합 로그 → 사건 조사 → 수집 품질.
- 에이전트: 에이전트 설치 파일 → 발급 키 관리 → 에이전트 접속 현황.
- 페이지별 메뉴 HTML이나 별도 모바일 메뉴를 다시 추가하지 않는다. 미구현 메뉴는 동작 가능한 기능처럼 표시하지 않는다.
- 페이지 본문의 업무별 안내와 버튼은 각 페이지에 유지한다. 공통 헤더는 서버 정상·수신 성공을 주장하지 않는다.

## 현재 위치와 모바일

주소 경로로 현재 메뉴를 표시한다. 루트는 관제 현황, `workbench.html`은 사건 조사다. `agents.html#keys`는 발급 키 관리 창을 열며 닫으면 설치 파일 메뉴로 복귀한다. 다른 화면에서도 같은 링크로 진입하고 새로고침할 수 있다. 키 원문이나 인증정보를 주소에 넣지 않는다.

700px 이하에서는 헤더의 메뉴 버튼으로 같은 사이드바를 펼친다. 키보드 Tab으로 메뉴에 접근하고 Escape로 닫아 버튼에 초점을 돌린다. 작은 화면에서도 메뉴가 누락되거나 이름이 바뀌지 않는다. 메뉴는 JavaScript로 렌더링되며 기존 데이터 조회도 JavaScript가 필요하다.

## 검증과 배포

`prototype/tests/shell.test.cjs`에서 공통 컴포넌트 참조·중복 제거·메뉴 순서·활성 상태를 검사한다. 키 관리 테스트는 직접 링크·닫기·재진입을 검사하고 포털 테스트는 공통 자산의 인증을 검사한다. UI 검증은 별도 합성 서버에서 하며 운영 배포나 실제 수신 증거를 대체하지 않는다.

서버 반영 시 HTML만 복사하지 말고 포털 이미지를 공통 JS/CSS와 함께 재빌드한다. 기존 배포 갱신 절차는 [사건 업무 가이드](incident_workflow.md)를 따른다.
