# 포털 공통 레이아웃

운영 화면 9개는 `prototype/shell.js`의 헤더·사이드바와 `prototype/shell.css`를 공유한다. 로그인은 같은 색상과 폼 스타일을 사용하되 메뉴는 표시하지 않는다. 각 HTML에는 `app-shell` 자리와 공통 자산 참조만 둔다.

## 메뉴 변경

- 메뉴 이름·주소·그룹·순서는 `shell.js`의 `groups`에서 한 번만 변경한다.
- 보안 관제: 관제 현황 → 통합 로그 → 재처리 이력 → 사건 조사 → 수집 품질 → 탐지 실행·제외 이력.
- 에이전트: 에이전트 설치 파일 → 발급 키 관리 → 에이전트 접속 현황.
- 페이지별 메뉴 HTML이나 별도 모바일 메뉴를 다시 추가하지 않는다. 미구현 메뉴는 동작 가능한 기능처럼 표시하지 않는다.
- 페이지 본문의 업무별 안내와 버튼은 각 페이지에 유지한다. 공통 헤더는 서버 정상·수신 성공을 주장하지 않는다.

## 현재 위치와 모바일

주소 경로로 현재 메뉴를 표시한다. 루트는 관제 현황, `workbench.html`은 사건 조사다. `agents.html#keys`는 발급 키 관리 창을 열며 닫으면 설치 파일 메뉴로 복귀한다. 다른 화면에서도 같은 링크로 진입하고 새로고침할 수 있다. 키 원문이나 인증정보를 주소에 넣지 않는다.

700px 이하에서는 헤더의 메뉴 버튼으로 같은 사이드바를 펼친다. 키보드 Tab으로 메뉴에 접근하고 Escape로 닫아 버튼에 초점을 돌린다. 작은 화면에서도 메뉴가 누락되거나 이름이 바뀌지 않는다. 메뉴는 JavaScript로 렌더링되며 기존 데이터 조회도 JavaScript가 필요하다.

## 검증과 배포

`prototype/tests/shell.test.cjs`에서 공통 컴포넌트 참조·중복 제거·메뉴 순서·활성 상태를 검사한다. 키 관리 테스트는 직접 링크·닫기·재진입을 검사하고 포털 테스트는 공통 자산의 인증을 검사한다. UI 검증은 별도 합성 서버에서 하며 운영 배포나 실제 수신 증거를 대체하지 않는다.

서버 반영 시 HTML만 복사하지 말고 포털 이미지를 공통 JS/CSS와 함께 재빌드한다. 기존 배포 갱신 절차는 [사건 업무 가이드](incident_workflow.md)를 따른다.

## 화면 원칙

- 제목·주요 작업·목록을 먼저 배치한다. 관제 메인은 지표와 경보를 사건 목록보다 먼저 보여준다.
- 안내는 필요한 위치에 한 번만 둔다. 집계 기준·문서 ID·규칙 버전·점수 계산·상세 통계는 펼쳐서 본다.
- 0건, 조회 실패, 미측정, 미수신을 구분한다. 오래된 목록을 최신 결과처럼 남기지 않는다.
- 키 폐기 영향, 메모 수정 불가, 개인정보 제한, 공격 성공 미확정은 짧게 표시한다.
- 로그인과 버튼·검색·폼을 같은 스타일로 맞춘다. 모바일 표는 내부에서 가로 스크롤한다.

로그인 전 필요한 자산은 `/login/styles.css`, `/login/agents.css`, `/login/mark.svg`만 별도 고정 경로로 제공한다.
일반 포털 파일과 데이터 API의 인증·권한·CSP는 유지한다.

## 2026-10-12 검증

UX-01은 `pack`의 로컬 화면 개선이다. 10개 페이지와 키 관리·사건 진입을 1440px/390px에서
26회 검사했고 주요 창 9종도 두 크기에서 확인했다. 설치 파일·시험 키·메모 작업은 임시 저장소,
세션 로그인은 실제 포털 코드, 로그·수집·탐지 응답은 합성 자료다. 운영 설치·수신·키 폐기 증명이 아니다.

재현: 기존 개발 시험 환경에서 `tests/preview_portal_ux.py` 실행 후 로컬 `/login`에 시험 계정으로 로그인한다.
CLI 브라우저 검증은 `tests/browser_portal_ux*.cjs`, 회귀는 `prototype/tests/ux.test.cjs`와 기존 UI 시험을 사용한다.
로그인 자산 제한은 `tests/test_portal.py`, 기존 조직·권한 회귀는 `tests/test_integration_security.py`에 있다.
서버 배포는 별도 요청 후 진행한다.
