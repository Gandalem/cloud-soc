# Cloud SOC

Windows·Ubuntu 로그와 네트워크 메타데이터를 모아 **위험 경보 → 근거 확인 → 사건 조사·기록**으로 연결하는 Mini SIEM 프로젝트입니다.

```text
서버·PC 에이전트 → Elasticsearch → 정규화·탐지 → 홈 대시보드·로그·사건 조사
```

현재 소스의 고객 화면은 홈·내 대시보드·통합 로그·사건 조사입니다. **새 대시보드와 메뉴 정리는 2026-10-12 지정 VMware에 보호 배포했습니다.** 기존 admin 비밀번호를 유지한 세션 로그인·실제 로그아웃·개인 설정 재시작 보존과 네 수집기 신규 수신을 확인했습니다. 추가 조직/역할·실제 위험 경보/사건의 전체 인수는 남아 있습니다. [현재 작업·검증 상태](docs/work_tracker.md)

## 1. 중앙 서버 설치

새 Ubuntu 서버에서 [중앙 서버 가이드](deploy/server/README.md)를 따릅니다. 지원 중앙 서버는 Ubuntu LTS·systemd 환경이며 용량·인증서·접근 IP 준비 기준은 해당 가이드에 있습니다.

```bash
git clone https://github.com/Gandalem/cloud-soc.git
cd cloud-soc
less deploy/server/install-ubuntu.sh
sh deploy/server/install-ubuntu.sh --dry-run
```

스크립트와 설치 계획을 검토한 뒤 `sudo sh deploy/server/install-ubuntu.sh`를 실행합니다. dry-run은 계획 출력이며 설치 가능 여부나 실제 기동 검증이 아닙니다.

설치 시 정한 주소의 `https://<중앙-서버-주소>/`에서 `admin`과 설치 때 설정한 비밀번호로 로그인합니다. 사설 CA는 출처·해시를 확인한 공개 인증서만 신뢰 등록합니다. 기본 관리자 비밀번호를 제공하지 않습니다.

기존 서버는 초기 설치기를 다시 실행하지 않고 [서버 업데이트](docs/agent_status.md#기존-중앙-서버-업데이트)와 [보호 백업](docs/portal_backup.md)을 따릅니다.

## 2. 에이전트 설치

1. 관리자로 **에이전트 설치 파일 → 설치 파일 추가**를 엽니다.
2. 운영체제·조직·시스템/웹/네트워크 수집 여부를 선택합니다. 시스템은 기본 활성화, 웹·네트워크는 선택 사항입니다. 웹에는 사이트 이름·서버 종류·파일 경로·시작 범위를 지정합니다. [통합 설치 지원 범위와 제한](docs/unified_site_agent.md)
3. ZIP/tar.gz를 다운로드하고 표시된 해시와 대조한 뒤 새 폴더에 압축을 풉니다.
4. 패키지에 표시된 수동 키 발급 또는 활성화된 설치 토큰 절차를 따릅니다.
5. **해당 패키지의 설치 명령**을 대상 PC/서버의 관리자 환경에서 실행합니다.

Windows는 64비트 관리자 PowerShell과 승인된 스크립트 실행 환경이 필요합니다. Ubuntu 에이전트는 22.04·systemd 범위입니다. Windows 네트워크 수집에는 승인된 Npcap, 양 OS의 네트워크 수집에는 올바른 인터페이스 선택이 필요합니다. [설치 상세](docs/installation_reference.md) / [네트워크](deploy/agents/NETWORK.md)

패키지는 중앙 주소·조직·공개 CA를 포함하며 수집 키를 내장하지 않습니다. 신규 Windows·Ubuntu의 단일 설치 토큰·자동 중앙 수신 확인은 서버에서 준비·활성화된 경우에 지원합니다. 기존 설치는 갱신/복구 절차를 사용합니다. [토큰 지원 범위](docs/agent_enrollment.md)

## 3. 대시보드 사용

| 고객 메뉴 | 목적 |
| --- | --- |
| 홈 대시보드 | 경보·수신 로그·진행 중 사건 요약, 추이와 최근 경보 근거 확인 |
| 내 대시보드 | 위젯·순서·너비·기간을 계정별 저장. 상단 버튼으로 전 화면 다크/화이트 모드 전환 |
| 통합 로그 | 조직·기간·호스트·수집기 검색, 로그 메타데이터와 보호된 상세 |
| 사건 조사 | 사건·담당자·상태·메모·판정·변경 이력 |
| 에이전트 설치 파일 / 발급 키 관리 / 에이전트 수신 현황 | 설치 준비, 키 만료·폐기, 마지막 중앙 수신 확인 |

홈이 관제 시작 화면을 맡습니다. 별도 관제 현황 메뉴, 수집 상태·분석 진단·과거 분석 이력 메뉴와 기술 위젯은 고객 화면에서 제외했습니다. 운영자용 진단 경로와 기록은 보존합니다. [대시보드](docs/dashboards.md) / [운영 진단](docs/processing_operations.md)

경보는 저장된 탐지 결과이며 공격 성공이나 차단 건수가 아닙니다. 경보 목록·심각도는 최신 최대 50건 범위입니다. 사건 집계는 미종결 사건 전체로 조회 기간과 별도입니다. 조회 실패·미측정은 0으로 바꾸지 않고, 분석 중단·지연 경고는 유지합니다.

<a id="7-설치-후-실제-로그-확인"></a>

### 로그가 들어오는지 확인

**통합 로그**에서 최근 서버 수신 시각과 호스트·수집기를 조회하고 **에이전트 수신 현황**에서 마지막 수신을 대조합니다. 설치 완료나 서비스 실행만으로 실제 중앙 수신을 판단하지 않습니다. 원본 시험 문서와 ES → API → 브라우저 대조는 별도 검증 단계입니다.

원문은 승인된 역할·조직·조회 사유·감사 기록을 확인한 보호 필드 JSON만 제공합니다. 메시지 본문·명령 인자·비밀정보·전체 원문 내보내기는 제한합니다. [조회 정책](docs/log_access_policy.md)

## 4. 기존 PC 갱신

기존 ZIP은 서버 업데이트로 바뀌지 않습니다. 같은 설치의 설정·키·registry·미전송 큐를 보존하며 [Windows Discovery 갱신](docs/windows_discovery_update.md), [중지 설치 복구](docs/windows_install_recovery.md), [Ubuntu/토큰 지원 범위](docs/agent_enrollment.md)를 따릅니다. 정상 설치에 신규 등록을 재실행하지 않습니다.

## 5. 문제 해결

설치 실패는 [설치 상세·오류 안내](docs/installation_reference.md#문제-해결), 로그인·조회 실패는 [중앙 서버 가이드](deploy/server/README.md), 분석 지연은 운영 담당자의 [처리 진단 절차](docs/processing_operations.md)를 확인합니다. 자격 증명과 실제 로그 본문을 이슈·문서에 기록하지 않습니다.

## 수집 범위와 검증 한계

Windows 이벤트 채널·지원 로그 폴더, Ubuntu journald·지원 텍스트 로그를 탐색하며 개인문서·키 파일·전체 디스크를 수집하지 않습니다. 네트워크는 흐름·DNS·TLS 메타데이터 범위이며 PCAP·본문·쿠키를 저장하지 않습니다. [수집 범위](deploy/agents/COLLECTION.md)

AWS CloudTrail·OCI Audit은 별도 권한·설정이 필요한 선택 수집기입니다. 기본 AUTH-001과 선택 탐지 프로필의 지원 필드·조건은 [탐지 범위](docs/detection_coverage.md)를 따릅니다. 모든 이벤트 해석·자동 공격 판정·차단을 제공하지 않습니다.

VMware의 Windows·Ubuntu 실제 수신과 보호 배포·분석 복구 기록은 [작업 이력](docs/work_history_20261012.md)에 있습니다. 새 UI의 추가 조직/역할 인수, SSH/PAM 위험 시나리오, 사건 저장·재시작의 전체 인수와 AWS 실제 연동은 남아 있습니다. 지정 시험 포털의 로그인은 `https://192.168.235.128/login`이며 로그아웃은 화면 상단에 있습니다. 구현·단위/격리 시험·배포·실수신을 별도로 기록합니다.
